# ผู้ช่วย AI (Local AI Assistant) — STEP 69-80

ผู้ช่วย AI ที่หน้า `/assistant` รันโมเดลภาษาบนเครื่องของคุณเองผ่าน **Ollama** — ไม่มีการส่งข้อมูลออกไป
นอกเครื่อง ไม่เรียก OpenAI/Anthropic หรือบริการ AI ภายนอกใดๆ สำหรับฟีเจอร์นี้

**สำคัญ: เบราว์เซอร์ไม่เคยเรียก Ollama โดยตรง** หน้า `/assistant`
(`src/app/assistant/page.tsx`) เรียกเฉพาะ `POST /api/assistant/chat` ซึ่งเป็น API route ของแอปนี้เอง
(`src/app/api/assistant/chat/route.ts`) — มีเพียง route นั้นเท่านั้นที่เรียก Ollama
(`http://127.0.0.1:11434`) และมีเพียง route เดียวกันเท่านั้นที่ Ollama ตอบกลับหา ไม่มี path ใดที่เบราว์เซอร์
เข้าถึง Ollama ตรงๆ เลย

## ก่อนใช้งานจริง

1. ติดตั้ง Ollama จาก [ollama.com/download](https://ollama.com/download) (รองรับ Windows/macOS/Linux)
2. ดึงโมเดลที่แอปนี้ใช้งานจริง (ชื่อโมเดลกำหนดตายตัวในโค้ด — ดูหัวข้อ "การตั้งค่า" ด้านล่าง):
   ```bash
   ollama pull qwen2.5:3b
   ```
3. ให้ Ollama รันอยู่เบื้องหลัง — ปกติ Ollama จะเริ่มทำงานอัตโนมัติหลังติดตั้งและฟังที่
   `127.0.0.1:11434` อยู่แล้ว ไม่ต้องตั้งค่าเพิ่มเติมในแอปนี้ (ไม่มี environment variable ใดๆ สำหรับ
   ฟีเจอร์นี้ — ดูหัวข้อถัดไป)
4. ต้อง login เข้าระบบหลังบ้านก่อนเสมอ (เหมือนทุกหน้า/ทุก API อื่นในระบบนี้) — `/assistant` และ
   `/api/assistant/*` ทุกเส้นทางถูกป้องกันด้วย `src/proxy.ts` เหมือนกันทั้งหมด ไม่มีข้อยกเว้น

## การตั้งค่า

ฟีเจอร์นี้**ไม่มี** environment variable ของตัวเอง — ค่าที่ใช้ทั้งหมดกำหนดตายตัวไว้ในโค้ด
(`src/app/api/assistant/chat/route.ts`):

| ค่า | ปัจจุบันคือ | ที่มา |
|---|---|---|
| Ollama base URL | `http://127.0.0.1:11434` | ตัวแปร `OLLAMA_BASE_URL` ในโค้ด (hardcoded) |
| โมเดล | `qwen2.5:3b` | ตัวแปร `OLLAMA_MODEL` ในโค้ด (hardcoded) |
| Timeout ต่อการเรียก Ollama หนึ่งครั้ง | 180 วินาที | ตัวแปร `OLLAMA_TIMEOUT_MS` ในโค้ด |
| จำนวนรอบ tool-call สูงสุดต่อ 1 คำถาม | 3 รอบ | ตัวแปร `MAX_TOOL_ROUNDS` ในโค้ด |

ถ้าต้องการเปลี่ยนโมเดลหรือ URL ต้องแก้ค่าคงที่เหล่านี้ในโค้ดโดยตรง — เอกสารนี้ไม่ได้แนะนำให้เปลี่ยน
runtime/configuration เพื่อให้ตรงกับเอกสาร เป็นการบันทึกค่าจริงที่ใช้งานอยู่ตอนนี้เท่านั้น

## ตรวจสอบว่า Ollama พร้อมใช้งาน

```bash
curl http://127.0.0.1:11434/api/tags
```

ควรได้ JSON กลับมาพร้อมรายการโมเดล — ตรวจว่ามี `"name":"qwen2.5:3b"` อยู่ในนั้น ถ้าเรียกไม่ติดเลย
(connection refused) แปลว่า Ollama ยังไม่ได้เริ่มทำงาน ให้เปิดแอป Ollama หรือรัน `ollama serve`

## ⚠️ ห้ามเปิด Ollama ให้เข้าถึงจากภายนอก

Ollama เองไม่มีระบบ authentication ใดๆ ในตัว — ใครก็ตามที่เข้าถึงพอร์ต `11434` ได้จะสั่งรันโมเดล/ดึง
ทรัพยากรเครื่องได้ทันทีโดยไม่ต้อง login ผ่านแอปนี้เลย **อย่า**:

- ตั้งค่า Ollama ให้ฟังที่ `0.0.0.0` หรือเปิด port `11434` ผ่าน firewall/router ออกสู่อินเทอร์เน็ต
- เปิด reverse proxy ชี้ตรงไปที่ `11434` โดยไม่มีชั้น authentication ของตัวเอง

การป้องกันที่แท้จริงของฟีเจอร์นี้คือชั้น login ของแอป (`src/proxy.ts`) ที่ครอบ `/api/assistant/*` ไว้
เท่านั้น — Ollama ที่ฟังอยู่แค่ `127.0.0.1` (ค่า default) ต้องเข้าถึงจากเครื่องเดียวกันเท่านั้นอยู่แล้ว ควร
คงค่านี้ไว้เสมอ

## Troubleshooting

ข้อความ error ที่หน้า `/assistant` แสดงจริง (จาก `route.ts`) และความหมาย:

| ข้อความที่เห็น | สาเหตุ | วิธีแก้ |
|---|---|---|
| "Local AI assistant is not available right now. Make sure Ollama is running locally." | เรียก `127.0.0.1:11434` ไม่ติดเลย | เปิด Ollama / รัน `ollama serve` แล้วลองใหม่ |
| "The local AI model returned an error. It may not be installed." | Ollama ตอบกลับมาแต่มี error (มักเพราะยังไม่ได้ `ollama pull qwen2.5:3b`) | รัน `ollama pull qwen2.5:3b` ตามหัวข้อ "ก่อนใช้งานจริง" |
| "AI assistant timed out. Please try again." | โมเดลตอบช้ากว่า 180 วินาทีในการเรียกครั้งนั้น (เครื่อง CPU ล้วนอาจใช้เวลา 30 วินาทีถึงหลายนาที ดูหมายเหตุใน `route.ts`) | ลองใหม่อีกครั้ง; ถ้าเกิดบ่อยให้พิจารณาเครื่องที่แรงขึ้นหรือโมเดลเล็กลง |
| "The assistant could not complete this request. Please try again." | โมเดลขอเรียก tool เกิน 3 รอบติดต่อกัน (ผิดปกติ) | ลองถามใหม่ด้วยคำถามที่ชัดเจนขึ้น |

## ทดสอบด้วยตัวเอง

หลังติดตั้งครบตามด้านบน login เข้าระบบแล้วไปที่ `/assistant` ลองพิมพ์ เช่น "มีสินค้าอะไรบ้าง" หรือ
"ยอดขายวันนี้เท่าไร" — คำตอบแรกมักใช้เวลา 30 วินาทีถึง 3 นาที (เครื่อง CPU ล้วน ไม่มี GPU ก็ใช้งานได้แต่
ช้ากว่า) ตามที่หน้าเว็บระบุไว้แล้ว
